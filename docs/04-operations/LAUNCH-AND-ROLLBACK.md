## ثالثاً — يوم الإطلاق

1. **نسخة ما قبل الإطلاق**: `npm run db:backup` — يُسجَّل اسم الملف في محضر الإطلاق.
2. وسم الإصدار في git: `git tag v1.0.0` — نقطة التراجع للكود.
3. `npm run db:deploy` (المهاجرات بالمالك، ثم تهيئة مستخدم التشغيل والتحقق منه) ثم تشغيل الخادمين بـ `NODE_ENV=production` — والتطبيق بـ `DATABASE_URL` وحده.
4. فحص الدخان (5 دقائق): الرئيسية، منتج، سلة، شراء بمبلغ رمزي، لوحة البائع، لوحة الإدارة، `/admin` بلا تنبيه أحمر.
5. **ساعة المراقبة الأولى**: لوحة الإدارة — طوابير، وتنبيهات الانحراف؛ و`logs/` للأخطاء.

## رابعاً — المراقبة في أول 72 ساعة

| ما يُراقب | أين | العتبة التي تستدعي قراراً |
|---|---|---|
| انحراف مالي أو مخزني | تنبيه أحمر في `/admin` | **أي** انحراف → تحقيق فوري، وتجميد السحوبات |
| دفعات «لا نعرف» معلّقة | طلبات pending_payment أقدم من 15 دقيقة | أكثر من 3 → فحص الاتصال بالبوابة |
| أخطاء الخادم | `logs/` | أكثر من 1% من الطلبات → تقييم التراجع |
| طلبات بلا قبول | طابور «قاربت مهلة القبول» | تواصل مع البائع قبل الإلغاء الآلي |

## خامساً — خطة التراجع

### متى نتراجع

- انحراف في منظر حفظ المال أو المحافظ لا يُفسَّر خلال ساعة.
- خطأ يمنع الشراء أو الدفع لأكثر من 15 دقيقة.
- ثغرة أمنية مستغلّة.

**القرار لصاحب المشروع**، ويُتخذ خلال 30 دقيقة من التنبيه.

### الخطوات (كما يمشيها التمرين حرفياً)

1. **إيقاف الكتابة**: إيقاف خادم الـ API (صفحة صيانة على الواجهة).
2. **نسخة الحالة الراهنة** قبل أي تراجع — للتحقيق لاحقاً: `npm run db:backup`.
3. **استعادة نسخة ما قبل الإطلاق** على قاعدة الإنتاج:
   ```bash
   dropdb basta && createdb basta && pg_restore -d basta <نسخة_ما_قبل_الإطلاق>.dump
   ```
4. **إرجاع الكود** إلى الوسم السابق: `git checkout <الوسم_السابق>` ثم `npm ci && npm run build`.
5. **التحقق**: `npm run verify:quick` — الحرّاس ومنظرات التدقيق وكل الاختبارات.
6. إعادة التشغيل وفحص الدخان.

### ما يُفقد بالتراجع — ومعالجته

الاستعادة تُرجع القاعدة إلى لحظة النسخة. ما كُتب بعدها (طلبات ودفعات) لا يعود. لذلك:

- **كل دفعة نجحت عند البوابة بعد النسخة** تُستخرج من لوحة البوابة بتاريخها، وتُطابَق مع نسخة «الحالة الراهنة» (الخطوة 2)، وتُردّ للمشترين أو يُعاد إدخال طلباتها يدوياً. لهذا نسخة الخطوة 2 **إلزامية**.
- سجل التدقيق في نسخة الخطوة 2 يحدّد كل إجراء بعد الإطلاق باسم منفّذه ووقته.
- التراجع الأفضل هو الذي لا يحتاج استعادة: خلل في الواجهة وحدها يُتراجع عنه بالكود فقط (الخطوة 4) بلا مسّ القاعدة.

### التمرين

```bash
bash scripts/rollback-drill.sh
```

ينسخ قاعدة العمل إلى قاعدة تجريبية منفصلة، ويأخذ نسخة ما قبل الإصدار وبصمة بياناتها (عدد الطلبات والقيود ومجموع الدفتر والمحافظ والإعدادات وآخر مهاجرة)، ثم يطبّق **إصداراً سيّئاً** (عمود جديد + فترة تعليق صفر + مهاجرة مسجّلة)، ثم يستعيد، ثم يتحقّق: البصمة بالحرف، والمخطط السيّئ زال، والحرّاس نجت، ومنظرات التدقيق صفر. يُعاد قبل كل إطلاق.
