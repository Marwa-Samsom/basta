# الإطلاق بلا دومين ولا استضافة مدفوعة: قائمة المهام

> نتيجة مسح شامل للباك والفرونت في 12 أكتوبر 2026، على `main` ومعه التعديلات الأربعة غير الملتزَمة من `feat/supabase-db`.
> **الهدف:** موقع حيّ على نطاقات فرعية مجانية، وكل الخدمات على خطط مجانية.

## البنية المقترحة (كلها مجانية)

| الطبقة | الخدمة | العنوان |
|---|---|---|
| الفرونت (Next 16، يُرسم على الخادم) | Cloudflare Workers عبر `@opennextjs/cloudflare` | `basta.<حساب>.workers.dev` |
| الـ API (NestJS، عملية واحدة) | Render Free Web Service (750 ساعة شهرياً) | `basta-api.onrender.com`، ويُخدم للمتصفح من نطاق الفرونت نفسه عبر بروكسي |
| قاعدة البيانات | Supabase Free، عبر Session pooler على 5432 | — |
| الصور ووثائق البائعين | Supabase Storage أو Cloudflare R2 (10 غيغابايت مجاناً) | — |
| البريد | Brevo Free (مُرسِل Gmail موثَّق، نحو 300 رسالة يومياً) | — |
| إبقاء الـ API مستيقظاً | cron-job.org أو UptimeRobot، كل 10 دقائق | — |
| الأخطاء | Sentry Free | — |
| البحث | **بدون Meilisearch**: الـ API يرجع تلقائياً إلى البحث في القاعدة | — |

> **لماذا لا نضع الفرونت والـ API كليهما على Render؟** خدمتان مستيقظتان طوال الشهر تحتاجان نحو 1488 ساعة، والحدّ المجاني 750 ساعة.

## أولاً: عوائق في الكود (لا إطلاق قبل حلّها)

- [ ] **1. السماح بالدفع والشحن الوهميين في الإنتاج بقرار صريح**
  - **المشكلة:** `apps/api/src/common/config/env.ts:107-118` يرفض الإقلاع إذا كان `NODE_ENV=production` ومعه `PAYMENT_PROVIDER=fake` أو `SHIPPING_CARRIER=fake`.
  - **ما لا يصلح:** تشغيل الإنتاج بـ `development` يُسقط Secure cookies و HSTS و CORS الصارم وفحص أقل الصلاحيات، ويفتح `/api/docs`.
  - **الحل:** متغيّر صريح مثل `ALLOW_FAKE_PROVIDERS=demo`.

- [ ] **2. لافتة «متجر تجريبي» ثابتة في كل الصفحات، وتعديل الدفع**
  - **المشكلة:** صفحة الدفع `apps/web/src/app/.../checkout/page.tsx:23-29` و`:399-416` تعرض البطاقات التجريبية الخمس.
  - **الحل:** نخفيها خلف المتغيّر نفسه، أو نستبدلها بـ «دفع عند الاستلام» أو «طلب تجريبي».
  - **انتبه:** شركة الشحن الوهمية تُسلِّم الشحنة بعد نحو 40 دقيقة، فتبدأ فترة الحجز ثم يُحرَّر مال البائع. هذا يحتاج قراراً منك (انظر القسم الرابع).

- [x] **3. تقديم الـ API من نطاق الفرونت نفسه** (نُفِّذ في 12 أكتوبر 2026)
  - **المشكلة كانت:** كوكي التجديد `SameSite=Strict`، والنطاقان `workers.dev` و`onrender.com` موقعان مختلفان، فلا يُرسَل الكوكي أبداً، وكل مستخدم يُطرد بعد 15 دقيقة.
  - **ما نُفِّذ، الممر:**
    - مسار في الواجهة `apps/web/src/app/api/v1/[...path]/route.ts` يمرّر كل طلبات `/api/v1/*` إلى `NEXT_PUBLIC_API_URL`، ويعيد الردّ كما هو ومعه `Set-Cookie`.
    - المتصفّح يطلب `/api/v1` النسبي (`apiBase()` في `lib/api.ts`)، وتصيير الصفحات على الخادم يكلّم الـ API مباشرةً.
    - CSP: `connect-src 'self'` وحده، والصور ما زالت من أصل الـ API.
  - **ما نُفِّذ، عنوان الزائر:**
    - كل الطلبات تصل الـ API الآن من خادم الواجهة، فالواجهة ترسل عنوان الزائر مع سرّ مشترك `EDGE_PROXY_SECRET`.
    - الـ API يصدّق العنوان بالسرّ وحده (`trustEdgeProxy` في `app.setup.ts`)، ومن يكلّمه مباشرةً لا يختار عنوانه.
  - **عند النشر:**
    - نفس `EDGE_PROXY_SECRET` في Cloudflare وفي Render.
    - `TRUST_PROXY=1` على Render.
  - **التحقق:**
    - 4 اختبارات جديدة في `trust-proxy.integration.spec.ts` واختباران في `env.spec.ts`.
    - تعديل `session-hardening.spec.ts` و`logout.spec.ts` لأن الكوكي صار على نطاق الواجهة.
    - تجربة يدوية: صفحة على `localhost:3000` والـ API على `127.0.0.1:4000` (موقعان مختلفان)، فيُجدَّد الرمز المنتهي عبر الممر وتكمل الصفحة.

- [ ] **4. نقل الملفات من القرص المحلي إلى تخزين سحابي**
  - **المشكلة:** القرص على Render يُمسح مع كل إعادة تشغيل أو نشر أو استيقاظ من النوم.
  - **المعنيّ بالأمر:** صور المنتجات (`catalog/infrastructure/product-images.ts:122`)، ووثائق البائعين (`vendors/infrastructure/document-storage.ts:13`).
  - **الوضع الحالي:** متغيّرات `S3_*` في `.env.example` غير مستخدمة في أي مكان.
  - **الحل:** محوِّل تخزين (bucket عام للصور، وآخر خاص للوثائق)، ثم تحديث `imageUrl` في `lib/storefront.ts:15-18` وإضافة نطاق التخزين إلى `img-src`.

- [ ] **5. إرسال بريد حقيقي**
  - **المشكلة:** كل القنوات تكتب ملفات في `outbox/` فقط (`notifications/infrastructure/channels.ts:13,46-62`)، فلا يصل تأكيد البريد ولا استعادة كلمة المرور ولا تنبيهات البائعين.
  - **الحل:** محوِّل SMTP (Brevo، أو Gmail بكلمة مرور تطبيق). خدمة Resend لا تصلح بلا دومين موثَّق.
  - **ملاحظة:** الرسائل النصية و WhatsApp تبقى معطّلة، ويجب ألا يعتمد عليها أي مسار.

- [ ] **6. إصلاح صورة Docker للـ API، أو الاستغناء عنها**
  - **المشكلة:** `apps/api/Dockerfile` يعمل بالمستخدم `node` على `/app` المملوك لـ root، فينهار عند `mkdirSync(uploads)`. وفيه أيضاً HEALTHCHECK مثبَّت على المنفذ 4000، ومرحلة deps لا تنسخ كل ملفات `package.json` الخاصة بالمساحات.
  - **البديل الأبسط:** بناء Node أصلي على Render:
    - البناء: `npm ci && npm run db:generate -w @basta/api && npm run build -w @basta/api`
    - التشغيل: `npm start -w @basta/api`
    - فحص الصحة: `/api/v1/health/live`

- [ ] **7. فرض `NEXT_PUBLIC_SITE_URL` وقت البناء**
  - **المشكلة:** `lib/seo.tsx:8` يرجع إلى `http://localhost:3000` إذا غاب المتغيّر، فتخرج `metadataBase` و sitemap و robots و JSON-LD كلها بعنوان localhost.
  - **أثر إضافي:** هذا المتغيّر هو قائمة CORS المسموحة في الـ API أيضاً.
  - **الحل:** إفشال البناء بدونه، كما يحدث الآن مع `NEXT_PUBLIC_API_URL`.

- [ ] **8. تجربة مبكرة لـ OpenNext على Cloudflare**
  - **الخطوة:** تشغيل `opennextjs-cloudflare build`.
  - **ما نتحقق منه:** حجم الـ Worker (الحدّ المجاني 3 ميغابايت مضغوطة، ومجلد الخادم الحالي 18 ميغابايت قبل الضغط)، ودعم `proxy.ts` الخاص بـ Next 16.
  - **إن فشلت التجربة:** Vercel Hobby يشغّل التطبيق بلا تعديل، لكنه لغير الاستخدام التجاري. أو نرفع الفرونت على خدمة Render ثانية، مع مشكلة حدّ الساعات المذكورة أعلاه.

## ثانياً: مهمّ قبل الإطلاق

- [ ] **9. المهام الدورية تتوقف حين ينام الخادم**

  - **المشكلة:** غير موجودتين، مع أن الموقع يجمع بيانات شخصية ووثائق هوية من البائعين.
  - **الحل:** إضافتهما إلى الـ seed، وربطهما من التذييل ومن صفحة التسجيل.

- [ ] **13. ملء متغيّرات الإنتاج في لوحتي Render و Cloudflare**
  - **الأسرار:** `JWT_ACCESS_SECRET` و`JWT_REFRESH_SECRET` و`PAYMENT_WEBHOOK_SECRET` (32 حرفاً أو أكثر لكل منها)، و`TOTP_ENCRYPTION_KEY` (32 بايت بصيغة base64).
  - **القاعدة:** `DATABASE_URL` (دور التطبيق) و`DATABASE_MIGRATE_URL` (المالك).
  - **العناوين:** `NEXT_PUBLIC_SITE_URL` و`NEXT_PUBLIC_API_URL` (عنوان Render الحقيقي)، و`EDGE_PROXY_SECRET` بالقيمة نفسها في الواجهة والـ API.
  - **التشغيل:** `TRUST_PROXY` و`NODE_ENV=production` و`MAIL_*` و`SENTRY_DSN`.
  - **المسارات:** `UPLOADS_DIR` و`OUTBOX_DIR` و`ERROR_LOG_PATH` تشير إلى `/tmp`.

## رابعاً: قرارات مطلوبة من صاحب المشروع

1. **ماذا يرى المشتري عند الدفع؟** طلب تجريبي واضح، أم «دفع عند الاستلام» يدوي، أم إغلاق الدفع وعرض الكتالوج فقط؟
2. **هل نترك الشحن الوهمي يُكمل الطلبات ويحرّر أموال البائعين تلقائياً؟** أم نوقف المهمّة ونحدّث الحالات يدوياً من لوحة الإدارة؟
3. **أين نخزّن الملفات؟** Supabase Storage (مزوّد واحد مع القاعدة) أم Cloudflare R2 (سعة مجانية أكبر)؟
4. **هل نقبل نوم الخادم مع pinger؟** البديل خادم لا ينام، وهو مدفوع.
